# 짝꽁 빙고 — 서비스 기획서

> 대한학생회 「짝꽁 사업」을 서비스화한 **팀 단위 데일리 미션 빙고**.
> 운영진이 2~4명으로 팀(조)을 편성하면, 팀원이 함께 빙고판을 꾸미고, 디스코드에서 `/인증` 명령으로 미션을 인증해 칸을 채운다. 빙고 줄을 가장 많이 채운 팀이 시상을 받는다.

---

## 1. 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 참여 단위 | **팀(조)**: 2~4명. 팀당 빙고판 1개 |
| 빙고판 | 5×5, 팀명 + 색(2가지 중 택1)을 정해 제출 |
| 미션 | 대면 미션(★ 5칸) + 비대면 미션(나머지 20칸) |
| 인증 | 디스코드 인증 채널에서 `/인증 번호:12` + 사진 첨부 → **봇이 자동 반영**, 운영진이 사후 검수·반려 |
| 시상 | 1등 팀, 2등 팀, 나머지 중 추첨 1팀 |
| 구성 요소 | ① 참여자용 웹 ② 어드민 ③ 디스코드 봇 ④ DB |
| 기술 스택 | Next.js + TypeScript + Prisma + PostgreSQL, 봇은 discord.js |

---

## 2. 핵심 규칙

### 2.1 팀 구성
- 운영진이 어드민에서 **팀을 편성**한다. 한 팀은 **최소 2명, 최대 4명**.
- 팀원은 디스코드 ID로 미리 편성할 수 있고, 로그인하면 자동으로 연결된다.
- 한 시즌에 한 사람은 한 팀에만 속한다.

### 2.2 빙고판 꾸미기 (시즌 시작 전)
1. **빙고판의 2가지 색 중 하나**(민트/핑크)를 고르고 **팀명**을 정한다.
2. 제시된 **후보 미션 리스트에서 팀별로 25개**를 골라 칸에 놓는다. 칸에는 미션 **번호**가 적힌다.
3. **색칠된 5칸 ★**((2,2) (2,4) (3,3) (4,2) (4,4))에는 **대면 미션만**, 나머지 20칸에는 **비대면 미션만** 놓을 수 있다.
4. 팀원 누구나 수정할 수 있고, 마지막에 저장한 내용이 적용된다. **시즌 시작 시각에 판이 잠긴다.**
5. 시작 전에 빙고판을 제출하지 않은 팀은 참여할 수 없다.

### 2.3 미션
| | 비대면 미션 | 대면 미션 |
| --- | --- | --- |
| 공지 | 시작일부터 **매일 오전 7시**, 하루 1개 | **시작일에 일괄** 공지 |
| 인증 기간 | 공지된 **당일 23:59까지** | **최종 마감 전까지** 언제든 |
| 소급 | 지난 미션 소급 인증 불가 | - |
| 칸 | 일반 20칸 | ★ 5칸 |

- 모든 미션에는 **번호**가 있다. (`/인증 12` 처럼 번호로 인증)
- 미션마다 **사진 필수/선택**을 정할 수 있다. 기본은 필수이고, 사진 없이 인증해도 되는 미션은 미션 설정에서 "사진 선택"으로 바꾼다.
- 모든 미션은 **팀원 모두가 참여한 것**을 기준으로 인정한다.

### 2.4 인증과 칸 채우기

인증 채널에서 **`/인증 번호:12 사진:(첨부)`** 를 입력한다. 봇이 아래를 검사하고, 모두 맞으면 **즉시 칸을 채운다.**

| 검사 | 실패 시 안내 (본인에게만 보임) |
| --- | --- |
| 인증 채널에서 사용했는가 | 인증 채널에서 사용해 주세요 |
| 웹에서 디스코드 로그인한 적이 있는가 | 먼저 로그인해 주세요 |
| 운영진이 편성한 팀에 속해 있는가 | 팀에 배정되지 않았어요 |
| 우리 팀이 빙고판을 제출했는가 | 빙고판을 제출하지 않았어요 |
| 그 번호의 미션이 있는가 | 없는 번호예요 |
| 그 미션이 **우리 팀 빙고판에** 있는가 | 우리 팀 빙고판에 없어요 |
| 인증 기간 안인가 (비대면=공지~당일 23:59, 대면=시즌 전체) | 아직 공지 전 / 기간이 지났어요 |
| 사진이 필요한 미션에 사진을 붙였는가 | 사진이 필요해요 |

- 성공하면 채널에 **인증 기록(사진 포함)** 이 공개로 남고, 새 빙고가 완성되면 🎉 문구가 나온다.
- 같은 미션을 다시 인증하면 칸은 한 번만 채워진다. (기록은 남음)

### 2.5 반려 (사후 검수)
- 운영진(문화체육위원회)이 어드민에서 사진을 확인하고, 문제가 있으면 **사유와 함께 반려**한다. 반려 즉시 칸이 비워지고 순위가 다시 계산된다. 반려는 복구할 수 있다.
- 운영진이 직접 **수동 인증 처리**(예: 대면 미션 현장 확인)도 할 수 있다.

### 2.6 시상
**상위 2팀 (1등·2등)** — 아래 순서로 비교한다.
1. **빙고 줄을 많이 채운 순서**
2. 빙고를 만들지 못했더라도 **빙고판에 채운 미션(칸) 수**
3. **대면 미션 수행 개수**

세 기준이 모두 같으면 동점이며, 어드민에서 시상할 팀을 직접 선택한다.

**추첨 1팀** — 1·2등을 제외한 나머지 팀 중 1팀에게 소정의 추가 상품.
- 각 팀이 **채운 칸의 개수만큼 쪽지**를 받는다. (많이 할수록 당첨 확률이 높다.)
- 어드민의 추첨 도구(가중 무작위)를 쓰거나, 임원들이 모여 직접 뽑고(촬영) 결과를 어드민에 입력해도 된다.

시즌이 끝나면 어드민에서 **최종 확정**한다. 확정하면 인증 접수가 닫히고 결과가 홈에 공개된다.

## 3. 사용자와 권한

| 역할 | 하는 일 |
| --- | --- |
| 참여자(팀원) | 디스코드 로그인 → 팀 빙고판 꾸미기 → 디스코드 `/인증` → 웹에서 현황·랭킹 확인 |
| 운영진(어드민) | 시즌/미션/팀 관리, 인증 검수·반려, 수동 인증, 추첨·시상 확정 |
| 시스템 | 미션 공지, `/인증` 처리, 칸 자동 반영 |

- 로그인은 **디스코드 OAuth** 만 사용하며, 지정한 서버(길드) 구성원만 참여할 수 있다.
- 어드민은 `ADMIN_DISCORD_IDS` 환경변수로 최초 지정하고, 어드민 화면에서 추가·해제할 수 있다.

## 4. 화면 설계

디자인 톤: **마스코트 무드** — 파스텔 민트 바탕, 연노랑·핑크 포인트, 두꺼운 외곽선과 입체 그림자, 둥근 글꼴. 모바일 우선(하단 탭 바). 어드민은 같은 색을 쓰되 외곽선을 약하게 해 표·폼이 읽기 쉽게 한다. 마스코트 이미지는 `public/mascot.png` 를 넣으면 전체에 반영된다.

### 4.1 참여자 웹
| 경로 | 화면 | 설명 |
| --- | --- | --- |
| `/` | 홈 | 시즌 상태, 우리 팀 요약, 오늘의 비대면 미션, 시상, TOP 3(확정 후 결과) |
| `/board` | 우리 팀 빙고 | 시작 전: 팀명·색·25칸 편집. 시작 후: 순위·줄·칸·대면 현황과 빙고판(칸마다 큰 번호) |
| `/missions` | 미션 | 오늘의 비대면, 대면 미션 목록, 지난 비대면 미션. 우리 팀 달성 여부 표시 |
| `/ranking` | 랭킹 | 팀 순위(줄 → 칸 → 대면), 확정 후 1·2등·추첨 표시 |
| `/how-to` | 이용 방법 | `/인증` 사용법, 규칙, FAQ |

### 4.2 어드민
| 경로 | 화면 | 설명 |
| --- | --- | --- |
| `/admin` | 대시보드 | 팀·인증 통계, 오늘 미션 현황, 미션별 달성, 점검 경고 |

| `/admin/submissions` | 인증 검수 | 사진 확인, 필터, 반려/복구 |
| `/admin/ranking` | 순위·시상 | 순위, 1·2등 선택, 가중 추첨, 최종 확정, CSV |

## 5. 디스코드 연동 (서버리스)

| 시점 | 동작 |
| --- | --- |
| 어드민에서 1회 | 서버에 `/인증` 명령 등록 |
| 매일 오전 7시대(크론) | 공지 시각이 지난 비대면 미션을 공지 채널에 올림 |
| 시즌 시작 후 첫 실행 | 대면 미션 목록을 한 번에 공지 |
| `/인증` | 8가지 검사 → 성공 시 사진을 포함한 인증 기록을 채널에 공개, 실패 시 본인에게만 사유 안내 |

디스코드가 `/인증`을 웹 주소(Interactions Endpoint)로 직접 보내주고, 서명(Ed25519)을 검증한 뒤 처리한다. **상시 켜 둘 봇 서버가 필요 없고**, Message Content Intent도 필요 없다.

## 6. 데이터 모델

```
User(discordId*, name, isAdmin)
Event(name, startAt, endAt=최종 마감, guildId, announce/verifyChannelId, prize1/2/Raffle, finalizedAt)
Mission(eventId, number*, type[REMOTE|FACE], title, requirePhoto, day, publishAt, deadlineAt)
Team(eventId, number*, name, color[MINT|PINK], submittedAt)
TeamMember(eventId, teamId, userId)   -- (eventId, userId) unique: 한 시즌 한 팀
TeamCell(teamId, position, missionId) -- 25칸
Submission(teamId, userId?, missionId, source[DISCORD|MANUAL], externalId*, replyMessageId,
           attachmentUrls[], postedAt, status[ACCEPTED|REJECTED], rejectReason)
Winner(eventId, kind[FIRST|SECOND|RAFFLE], teamId, lines, filled, faceCount)
```

- 칸의 달성 여부는 별도 저장하지 않고 **(팀, 미션)에 ACCEPTED 인증이 있는지**로 계산한다. 반려·복구·중복이 자연스럽게 처리된다.
- 순위도 항상 인증 기록으로부터 계산한다.

## 7. 시스템 구조

```
[참여자 브라우저] ──► Next.js (참여자 웹 + 어드민 + OAuth)  ──┐
                                                           ├──► PostgreSQL
[디스코드 서버]  ──► /인증 (웹훅) ─────────────────────────┤
                 ◄── 미션 공지 (Vercel 크론) ───────────────┘
```

- 웹·어드민·`/인증` 처리·공지가 모두 한 Next.js 앱이고, 빙고·순위·인증 판정 로직은 공용 모듈이다.
- 배포: **Vercel(앱) + Neon(Postgres)**. 무료 플랜의 크론은 하루 한 번(해당 시각대 중 한 시점)이라, 정각 공지가 중요하면 어드민의 "지금 미션 공지 실행"을 쓴다.

## 8. 운영 흐름

1. **준비** 시즌 생성 → 미션 등록(대면 5개 이상, 비대면 20개 이상) → 비대면 일정 자동 배정 → 팀 편성
2. **시작 전** 팀원들이 로그인해 팀명·색·빙고판 제출 (미제출 팀 점검)
3. **시작일** 판 잠금, 대면 미션 일괄 공지
4. **매일** 오전 7시 비대면 미션 공지 → `/인증` → 봇 자동 반영 → 운영진 사후 검수
5. **종료** 순위 확인 → 1·2등 선택 → 추첨 → 최종 확정

## 9. 합의하지 못해 가정한 부분 (바꾸려면 알려주세요)

1. 빙고판은 5×5로 고정한다. (대면 ★ 칸 위치가 5×5 기준이라서)
2. ★ 5칸에는 대면 미션만, **나머지 20칸에는 비대면 미션만** 놓을 수 있다.
3. 규칙의 "팀원 모두 참여"는 시스템이 강제하지 않고, **운영진이 사진으로 확인해 반려**한다.
4. 빙고판 색은 **민트 / 핑크** 2가지로 정했다. (색은 `src/lib/rules.ts`·`globals.css`에서 바꿀 수 있다.)
5. "빙고판 꾸미기"는 **팀명 + 색 선택**으로 구현했다. (스티커 등 추가 꾸미기는 없음)
6. 비대면 미션 마감은 당일 23:59:59까지 인정한다.
7. 시간대는 KST 고정, 동시에 진행하는 시즌은 하나다.
8. 기존 "인증 카톡방"은 **디스코드 인증 채널**로 대체한다.
9. 무료 플랜의 크론 특성상 비대면 미션 공지는 **오전 7시대 중 한 시점**에 올라간다. (인증 가능 시간은 공지 시각 07:00부터 정확히 적용된다.)
10. 인증 메시지를 지워도 자동 반려되지 않는다. (게이트웨이 상시 접속이 필요해서 제외, 어드민에서 직접 반려)
